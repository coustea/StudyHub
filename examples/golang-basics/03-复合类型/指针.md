# 指针

Go 保留指针，但去掉了指针运算，因此比 C/C++ 安全得多。指针主要用来**共享数据**和**在函数中修改外部变量**。

## 地址与指针变量

```go
x := 42
p := &x        // p 是 *int 类型，保存 x 的地址

fmt.Println(p)  // 0xc0000120a0
fmt.Println(*p) // 42，解引用读取
```

- `&变量` 取地址。
- `*指针` 解引用，读写指向的值。

```go
*p = 100
fmt.Println(x) // 100
```

## 指针类型与零值

```go
var p *int     // nil 指针
var q *string
```

指针的零值是 `nil`。解引用 nil 指针会 panic：

```go
var p *int
fmt.Println(*p) // panic: runtime error: invalid memory address
```

使用前确保指针非 nil：

```go
if p != nil {
    fmt.Println(*p)
}
```

## new 与 make

`new(T)` 为类型 T 分配零值内存，返回 `*T`：

```go
p := new(int)
fmt.Println(*p) // 0
*p = 10
```

`make` 只用于 slice、map、channel，返回的是类型本身而不是指针：

```go
s := make([]int, 3)
m := make(map[string]int)
ch := make(chan int)
```

## 指针作为函数参数

Go 函数参数是**值传递**。想修改外部变量，需要传指针：

```go
func addOne(n int) {
    n++
}

func addOnePtr(n *int) {
    (*n)++
}

x := 1
addOne(x)       // x 仍是 1
addOnePtr(&x)   // x 变成 2
```

结构体的指针接收者方法本质就是这个机制。

## 指针与逃逸分析

编译器会通过**逃逸分析**决定变量分配在栈还是堆：

```go
func newUser() *User {
    u := User{Name: "Alice"}
    return &u // u 逃逸到堆上
}
```

程序员不需要手动管理内存，GC 会自动回收不可达对象。逃逸分析可通过 `go build -gcflags=-m` 查看。

## 指针与切片 / map 的区别

```go
func modifySlice(s []int) {
    s[0] = 99        // 会影响调用方
    s = append(s, 4) // 不一定影响调用方的长度
}

func modifyMap(m map[string]int) {
    m["a"] = 1       // 会影响调用方
}
```

切片本身是包含指针、长度、容量的小结构体，值传递时复制了这个结构体，但底层数组共享。map 本身就是指向底层结构的引用。

## 多级指针（了解）

```go
x := 10
p := &x
pp := &p
fmt.Println(**pp) // 10
```

实际应用很少，超过两级通常说明设计需要重构。

## 指针的常见误区

### 不要返回局部变量的指针？

这是安全的，Go 的逃逸分析会自动把变量分配到堆上：

```go
func counter() *int {
    n := 0
    return &n // 完全合法
}
```

### 循环变量取地址

Go 1.22 之前循环变量是同一个变量，取地址会得到相同指针。1.22 起每次迭代独立。兼容旧版本要显式复制：

```go
for _, v := range values {
    v := v
    ptrs = append(ptrs, &v)
}
```

## 什么时候用指针

- 需要在函数中修改调用方的变量。
- 避免复制大结构体。
- 表示"可选值"：`nil` 表示不存在。
- 类型的方法需要修改接收者状态。

不需要用指针的场景：小结构体、基本类型作为只读参数、slice/map/channel（本身已经是引用语义）。

## 小结

- `&` 取地址，`*` 解引用，nil 指针不能解引用。
- `new(T)` 返回 `*T`；`make` 用于引用类型。
- 函数参数始终值传递，修改外部状态要传指针。
- Go 有 GC，指针不会造成悬垂引用，但共享数据仍需 concurrency 控制。
